# Issue #8 completeness review: vector values in the DUT retire trace were read too late
# sigil-verify, 2026-10-22 UTC. Spike 2c300cd9, Verilator 5.048. Simulation-only probe
# (rtl/core/sigil_core.sv, SIGIL_COMMIT_TRACE); the design itself was not affected.

  e1 m=0 old=cb           expected=cb ref=cb dut=ec   (masked off, must be unchanged)

  e5.. tail: ref = dut = old
Spike's value is the spec result in every element. The DUT's logged
elements 0-4 are bytes 0-4 of buffer B (s3), which the next instruction,
vle8.v v24,(s3), loads into v24 (the same bytes as v3, loaded from s3
earlier in the iteration; seed 8, e8 m4 vl 26, shows the same).

A minimal program (vslide1down/vslide1up masked and unmasked, back to
back, no vector load after them) matched Spike, so the unit computes
the right result.

## Cause
The probe printed the vector registers an instruction wrote from its
VRF shadow at retirement (WB). A vector load in MEM stalls the pipeline
(mem_stall), and the retire condition includes !mem_stall, so the older
instruction waits in WB while the load writes the VRF: its registers
were printed with the load's data in elements [0, vl).

## Fix (862868c)
The rows the instruction wrote are copied from the shadow as it enters
WB, with that edge's VRF write merged in, and printed from the copy.
A younger vector arithmetic op cannot write before that edge (it writes
at least three cycles after it starts in EX), and a younger vector load
writes only from its MEM access cycles on.
