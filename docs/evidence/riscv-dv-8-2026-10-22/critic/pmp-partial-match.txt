## Rule (RISC-V privileged spec, "Priority and Matching Logic")
"The lowest-numbered PMP entry that matches any byte of an access
determines whether that access succeeds or fails. The matching PMP entry
must match all bytes of an access, or the access fails, irrespective of
the L, R, W, and X bits." So the access fails, in M-mode too. Spike
implements exactly this (riscv/mmu.cc at 2c300cd9, pmp_lookup):
    for (size_t i = 0; i < pmp_num; i++) {
      // Check each 4-byte sector of the access
      bool any_match = false;
      bool all_match = true;
      for (reg_t offset = 0; offset < len_aligned; offset += gran) {
        bool match = proc->state.pmpaddr[start + i]->match4(addr_aligned + offset);
        any_match |= match;
        all_match &= match;
      }
  
      if (any_match) {
        // If the PMP matches only a strict subset of the access, fail it
        if (!all_match)
          return &always_fail_pmp;
  
        return proc->state.pmpaddr[start + i].get();
      }
    }

## Cause (rtl/core/sigil_csr.sv at adf4c97)
pmp_check() matched each entry against addr[55:2] only: the first 4-byte
word of the access, whatever its size. With the 4-byte grain (G=0) an NA4
entry or a TOR boundary can split an 8-byte access (scalar or FP load or
store, AMO, LR/SC, 64-bit vector element, the walker's PTE read and A/D
write-back). Such an access was allowed or denied by the entry that
matches its first word (or by none, when only the second word matched),
so in M-mode with L=0 it always succeeded. NAPOT regions are at least 8
bytes and naturally aligned, so they never split an aligned access;
accesses up to 4 bytes are aligned and stay in one word; fetches are
checked per 4-byte word as before.

## Fix (3ae351d)
pmp_match() returns the match for the access's word and for the next word
({addr[55:3], 1}; 8-byte accesses are 8-byte aligned, misaligned accesses
trap). pmp_check() takes the access width (pmp_wide_*_i: the data port's
access size is 8 bytes; the walker port always) and fails an access that
the deciding entry matches only in part. For TOR the second word's match
reuses the first word's magnitude compares plus two equality compares
(a54 + 1 == pmpaddr[i-1], a54 + 1 == pmpaddr[i]). Behaviour changes only
for accesses that some entry matches in part.
