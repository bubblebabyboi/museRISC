## 1. What 3ae351d changes
pmp_match returns {m1, m0}: the 4-byte word at the address and the word after it ({addr[55:3],1}).
pmp_check(wide) lets the lowest-numbered entry matching either word decide and fails the access if
that entry matches only one of them, in every mode and whatever L/R/W/X. Ports:
  A fetch   wide = 0 (one 4-byte word per fetch; a 32-bit parcel straddling two words is fetched as
            two words, the second with tval = pc+2)       -> function unchanged (proven, section 5)
  B data    wide = mem_size_code == 3 (ld/sd/fld/fsd, c.ld/c.sd/c.fld, AMO*.d, LR.d/SC.d, HLV.D/HSV.D
            via the decoder's rewritten funct3, vector elements of EEW 64 incl. indexed with SEW 64)
  C walker  wide = 1 (PTE reads and A/D write-backs, also G-stage: one walk_addr port)
Checked by reading: TOR m1 = (lo || prev == a54o) && hi && enc != a54o is a54o in [prev, enc) for
a54o = a54 + 1 (wide accesses are 8-byte aligned: misaligned traps first, vls_misalign has priority
over mem_pmp_fault in the MEM exception mux); NA4 m1 = (enc == a54o); NAPOT (>= 8 bytes, aligned)
matches both words or neither. A lone SC.d is checked too: Spike 2c300cd9 check_load_reservation
translates with the full size, so a partially matched lone SC.d faults (cause 7) on both.

## 4. Residual deviation: whole-register loads with EEW=64 (pre-existing, not caused by 3ae351d)
The VLS sequencer moves whole registers byte by byte (vls_eew_code = 0 for VLS_WHOLE), so
mem_size_code is 0 and 3ae351d's wide check never applies to vl<n>re64.v, whose architectural
elements are 8 bytes (evl = NFIELDS*VLEN/64, vstart counts them). Spike and Sail perform each
element as one 8-byte access. pmp_whole64_directed:
  1 M, NA4 over word 1 of element 1:      Spike/Sail fault tval buf+8 vstart 1; core no trap
  2 U, TOR [0, buf+20):                    Spike/Sail tval buf+16 vstart 2;       core tval buf+20
  3 vl1re8.v control:                      all tval buf+20 vstart 20
  4 M, vl2re64.v, NA4 over element 9:      Spike/Sail fault; core no trap
vec_trap_directed test 13 (same configuration as test 2) asserts the core's mtval pbuf+20.
Candidate fix (branch 8-dvfix-pmp-w64): check the first byte of each element of an 8-byte-aligned
vl<n>re64.v as the whole element:
  pmp_wide_data = (mem_size_code == 2'b11) || (vls_is && vls_whole && vls_idx_eew == 3'd3 &&
                  exmem_addr_q[2:0] == 3'd0 && mem_va[2:0] == 3'd0)
(a misaligned base keeps per-byte checks; a misaligned element may be split). Faults then land on
the element's first byte: tval = element address, vstart = byte >> 3. vec_trap_directed 132 is
updated to pbuf+16. Gates on the candidate: make lint (5.048) clean; make core-test rc=0, 305 TB
PASS, 0 FAIL (2,643 s, VJOBS=6); riscv-dv as in section 2. Not run: Verilator 5.020 lint, ACT,
riscv-tests.
