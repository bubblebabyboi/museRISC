# ACT4 DUT config: Sigil in-house core

DUT configuration for running riscv-arch-test (ACT4) against
the in-house RV64 core in `rtl/core/` (issue #18 stage 3d).
The canonical copies live here; `scripts/build_act4_core.sh`
syncs them into `third_party/riscv-arch-test/config/cores/
sigil-core/` before generating ELFs, and
`sim/run_act_core.sh` executes them on the core through
`tb/cpp/core_tb.cpp` (ELF/HTIF mode).

- `sigil-core.yaml` — UDB configuration. Every value was
  read out of the RTL (citations inline). Declared scope:
  RV64IM + Zicsr/Zifencei/Zicntr, M/S/U, Sv39+Svbare+Svnapot+
  Svadu, PMP16, IALIGN=32.
- `sail.json` — Sail reference configuration, derived from
  `sw/act4-cva6/sail.json` with only these overrides:
  mcountinhibit/mcounteren/scounteren writable-bit masks
  (0x5 / 0x7 / 0x7), no writable HPM counters, hpmevent
  width 64, mtvec/stvec vectored base alignment 2²,
  medeleg delegatable bits 0xB35D, mstatus FS legal = Off,
  PMP {grain 0, count 16, usable 16, NA4 on}, platform
  vendorid 0 / archid 0x5349474C / impid 0x30000,
  `wfi_is_nop` and `wfi_available_to_user_mode` true, and
  extensions flipped off (A, F, D, B, Zaamo, Zalrsc,
  Zicond, Zihpm, Zca/Zcb/Zcd, Zba/Zbb/Zbs/Zbc, Zbkb/Zbkc,
  Zknd/Zkne/Zknh, Svade) with Svadu flipped on, and the V
  `support_level` set to `Float_double` (Zve64d, stage 9;
  was `Integer` for stages <= 8). Everything
  else (memory regions, misaligned policy, platform) is
  inherited unchanged.
- `link.ld`, `rvmodel_macros.h` — copied from
  `sw/act4-cva6/` with header notes rewritten; the HTIF
  tohost halt convention is identical in this harness.

Generation (as run for the evidence in
`docs/evidence/act-core-impriv-2026-10-13.csv`):

1. `./scripts/build_act4_core.sh` (EXTENSIONS=I,M)
2. `EXTENSIONS=ExceptionsSv,ExceptionsSvSm,PMPS,PMPSm,PMPU,
   PMPF,Sv,SvPMP,SvSm,SvbareSm,SvaduPMP,Sv39,Svbare,Svnapot,
   Svadu ./scripts/build_act4_core.sh`
3. `EXTENSIONS=Zaamo,Zalrsc,F,D,Zba,Zbb,Zbc,Zbs,Zbkb,Zbkc,
   Zbkx,Zicond,Zkne,Zknd,Zknh ./scripts/build_act4_core.sh`,
   then the A-priv variants by suite name:
   `EXTENSIONS=ExceptionsSvZaamo,ExceptionsSvZaamoSm,
   ExceptionsSvZalrsc,ExceptionsSvZalrscSm,PMPZaamo,
   PMPZalrsc ./scripts/build_act4_core.sh`
4. `EXTENSIONS=Zca,Zcb,Zcd ./scripts/build_act4_core.sh`
   (also yields the ZcbZba/ZcbZbb/ZcbZmmul combined suites)
   Vector suites are generated by a separate ACT target first:
   `make -C third_party/riscv-arch-test vector-tests
   EXTENSIONS=Vx8,...,Vf64` (inside `mise exec`), then
   `EXTENSIONS=Vx8,Vx16,Vx32,Vx64,Vls8,Vls16,Vls32,Vls64,Vf32,Vf64
   ./scripts/build_act4_core.sh`. Move the sources listed in
   `docs/evidence/act-vector-core-genfail-2026-10-14.csv` out of
   `tests/rv64i/` first, or one Sail failure blocks every link.
5. `bash sim/run_act_core.sh <out.csv>`

No-vector core (SIGIL_NO_VECTOR, issue #13): `ACT_CONFIG=novec`
on any of the generation steps above uses the `sigil-core-novec`
config, which `scripts/act4_novec_config.py` derives from the files
here on every run (no Zve*/Zvl* extensions and no vector
parameters in the UDB config, `MSTATUS_VS_LEGAL_VALUES: [0]`, Sail
V `support_level` `Disabled`). ELFs land in
`work/sigil-core-novec/elfs/`; run them on the no-vector harness:
`make -C sim ../build/sim/core_tb_novec`, then
`CORE_TB=build/sim/core_tb_novec bash sim/run_act_core.sh <out.csv>
third_party/riscv-arch-test/work/sigil-core-novec/elfs`. Only the
non-vector suites (steps 1-4) apply.

Warning: the ACT make does not track DUT config files as
dependencies. After changing `sigil-core.yaml`/`sail.json`
in a way that alters architectural parameters (e.g. adding
C changes IALIGN 32→16 and every trap-signature
expectation), delete the affected suites under
`third_party/riscv-arch-test/work/sigil-core/{build,elfs}/`
and regenerate, or stale ELFs will silently test the old
configuration. This bit stage 5: `ExceptionsSv` appeared to
fail against pre-C signatures until `build/priv` and
`elfs/priv` were regenerated.
